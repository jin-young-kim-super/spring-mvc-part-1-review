Tomcat의 구조
HTTP 커넥터 (HTTP Connector) : 네트워크 연결 및 HTTP 통신 처리
↓
서블릿 컨테이너 (Servlet Container) : 서블릿 생명주기 관리, 요청·응답 객체 준비, 서블릿 호출

실제 요청 흐름 
브라우저에서 http://localhost:8080/hello에 요청을 보내면 다음과 같이 동작해. 
1. Tomcat의 HTTP 커넥터가 네트워크 연결을 받아 HTTP 요청을 처리해. 
2. 서블릿 컨테이너가 해당 요청을 처리할 서블릿을 결정하고 HttpServletRequest, HttpServletResponse 객체를 생성(이때 서블릿 컨테이너가 HTTP 메세지를 파싱하여 요청/응답 메시지를 삽입)
3. HttpServlet의 service() 가 HTTP 메서드에 따라 doGet(), doPost() 등을 호출해. 
4. 개발자가 작성한 서블릿이 비즈니스 로직을 실행해.

서블릿 컨테이너의 역할
스프링 컨테이너가 빈 객체 생성/관리하는 기능만 있는 게 아니라 메시지 기능, 국제화 기능 등의 부가 기능이 있는 것처럼 서블릿 컨테이너도 서블릿 객체의 생성/관리 기능만이
있는 것이 아니라 파싱, 서블릿 객체 호출 같은 부가 기능이 존재!!
