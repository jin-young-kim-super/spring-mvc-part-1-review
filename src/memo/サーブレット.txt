톰캣 VS 서블릿
-> 난 여태껏 톰캣이 HTTP 요청부터 HTTP 응답까지의 작업을 대신 해주는 줄 알았다(EX. 서버 TCP/IP 대기, 소켓 연결, HTTP 요청 메시지 파싱, Content-Type 확인, HTTP 응답 메시지 생성,
TCP/IP에 응답 전달, 소켓 종료). 
그러나 본질적으로는 서블릿이 이 기능들을 구현해 놓은 것이고, 톰캣이 이걸 가져다 쓰는 것 뿐이다. 
※크게 나누면 HttpServletRequest, HttpServletResponse가 위 작업들을 대신해 주는 것이고, 그 덕분에 개발자는 비지니스 로직 개발에만 집중 가능.

서블릿 컨테이너 : 서블릿을 지원하는 WAS(톰캣)
-> 톰캣의 역할은 서블리(서블릿 컨테이너 등)을 사용하여 서블릿 객체의 생성,초기화,호출,종료 등의 [생명 주기 관리] 역할이다. 
※물론, 생명주기 관리 이외에도 동시 요청을 위한 멀티 쓰레드 처리 지원이라는 매우 큰 이점이 있다.
