자바의 WAS 정의
-> 서블릿 컨테이너를 제공해야지만 WAS이다(물론, 서블릿 없이 자바 코드를 실행하는 서버 프레임워크도 있기는 함)

웹 서버와 WAS의 분리
-> WAS는 정적 리소스, 애플리케이션 로직 모두 제공 가능. 
그러나 이렇게 되면 아래의 문제점이 생긴다. 
・WAS가 너무 많은 역할을 담당함으로, 서버 과부하(작은 서비스면 그런 걱정 없음)
・정적 리소스 때문에 비용이 많이 드는 애플리케이션 로직 수행 어려움
・만약 WAS 서버 셧다운 시, 오류 페이지(뷰 페이지)를 보여 주는 것도 불가능해 진다.

해결책 : 클라이언트 -> 웹 서버 -> WAS -> DB 아키텍처!!
-> 클라이언트의 요청을 웹 서버가 먼저 받아서 정적 리소스만 필요한 경우 WAS까지 요청이 전달되지 않고 바로 응답 가능(서버 과부하 문제 해결)
그리고 만약 WAS나 DB가 셧다운이 돼도 웹 서버는 오류 페이지(정적 뷰 페이지)를 클라이언트에 응답 가능. 
또한 효울적인 리소스 관리가 가능해 진다. 
만약에 정적 리소스가 많아지면 웹 서버만 증설하면 되고, 동적인 애플리케이션 로직이 많아지면 WAS만 증설하면 된다. 
※참고로, 웹 서버는 셧다운이 거의 없다. 왜냐하면 애플리케이션 로직 같은 연산이 없기 때문이다. 잘 죽는 것은 대부분 WAS, DB이다.
※그러나 요즘은 SPA 방식의 개발이기에 WAS는 API를 담당하고, 웹 서버는 잘 두지 않는다. 웹 서버 대신에 리액트/앵귤로 같은 프론트 프레임워크로
웹 서버를 대체한다.
