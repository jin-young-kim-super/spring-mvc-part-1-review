서블릿의 한계 : 뷰 화면을 만드는 자바 코드 작성이 지저분하고 복잡
JSP의 한계 : 뷰 화면 부분에 자바 코드를 넣어서 가독성이 올라갔으나, jsp 파일 하나에 비지니스 로직과 HTML 로직이 동시에 존재한다. 
실무의 경우, HTML 코드는 수천 줄도 가능하다. 그리고 이런 JSP 파일이 수천 수백 개가 있다면 유지/보수가 매우 힘들다. e

MVC의 탄생 : 비지니스 로직과 뷰 영역을 분리!!
-> JSP는 목적에 맞게 HTML로 화면 렌더링에만 집중하게 만들고, 비지니스 로직은 철저히 분리. 
그래서 MVC 패턴이 탄생하였다(MVC : Controller와 VIew 사이에 Model을 끼워 놓고, 비지니스 로직을 통해서 View에 필요한
데이터를 Model에 담아 전달!
