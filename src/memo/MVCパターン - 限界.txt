딱 한 마디로 요약 : 공통 처리가 어렵다. 
-> 예를 들어, 각 컨트롤러(서블릿)이 호출될 떄마다 로그 처리를 해야 한다고 하자!
단순히 로그 기능을 메서드화 만들어서 호출하면 될 것 같지만, 각 서블릿마다 메서드를 호출해야 하며 또한 실수로 호출 누락이 있을 수가 있다.  
그리고 애초에 매번 호출하는 것조차 중복이다. 

프론트 컨트롤러 패턴 : 공통 처리를 컨트롤러 호출 전에 할 수 있게 해준다. 
-> 스프링의 DispatcherServlet도 프론트 컨트롤러이다.

프론트 컨트롤러의 특징
1. 서블릿으로 등록되며 단 하나의 서블릿으로 컨트롤러를 호출
2. 공통 처리 기능
3. 프론트 컨트롤러를 제외한 나머지 컨트롤러는 더이상 HttpServlet같은 것을 상속 받지 않아도 된다.
-> 왜냐하면 이제 공통처리가 가능하기 떄문에 service(request,response) 처리를 프론트 컨트롤러에서 할 것이기 때문이다
